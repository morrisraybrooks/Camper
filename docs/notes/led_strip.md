# project-camper-led-strip

> Alitove WS2811 12V addressable strip for camper; Athom LS-5P (PWM RGBW) can't drive it; WLED controller on order

2026-10-29: User has an **Alitove WS2811-300WH-IP65** strip (12V, 300 LEDs ≈ 100 pixels, 3 LEDs/IC) and an **Athom LS-5P** (PWM RGBW controller, no data line). They are incompatible; I explained why. Agreed plan: buy a **12V WLED (ESP32) controller**, added to `todo.shopping_list` as "WLED controller 12V for LED strip (Amazon)".

**How to apply:** when it arrives: WLED-AP setup → camper Wi-Fi → add WLED integration in HA, set 100 LEDs, 10A fuse on 12V, big colour tile on camper dashboard ([[project-camper-dashboard-colors]], [[user-low-vision]]). LS-5P is spare, good for a plain RGB/RGBW strip.

**2026-10-31 WLED installed:** user plugged a bare ESP32 (ESP32-D0WD, 4MB, CP2102, MAC 30:ae:a4:96:e7:cc) into the Pi (/dev/ttyUSB2). Flashed WLED 16.0.1 from the Pi: esptool pip-installed in the SSH add-on (`sudo env PYTHONPATH=~/.local/lib/python3.14/site-packages python3 -m esptool`; container reset wipes it), files in ~/wled. Offsets: bootloader_esp32_8m.bin @0x1000 (`--flash-size 4MB` re-flags it), partitions_c3_4m.bin @0x8000, app @0x10000, from the wled/WLED-WebInstaller **master** branch. Wi-Fi sent over USB with the Improv serial protocol, using the TP-Link_2.4 creds in esphome/secrets.yaml. Now **192.168.0.183**, name "Camper LED Strip", 100 LEDs WS281x GRB on **GPIO16**. Still to do: add to HA (auto-discovered), check colour order once the strip is wired, dashboard tile.
**2026-10-31 Porch = WLED:** WLED added to HA (zeroconf flow) as `light.camper_led_strip`. The strip IS the camper **Porch** light. `input_boolean.camper_porch_light` was replaced everywhere in camper.yaml (Home + Lights Porch tiles, Lights badge count) and in the Goodnight script (now `light.turn_on`, continue_on_error). Porch tiles: tap = toggle, hold = more-info (colour/brightness). Phone generator re-run. Backups `claude_backups/*.bak-preclaude-wledporch-*`. The old input_boolean was deleted from configuration.yaml the same day (backup *.bak-preclaude-rmporch-*); the WLED strip is the only porch entity.
**2026-11-01 first light:** strip works. Alitove wire colours CONFIRMED by testing: **white = GND, green = DATA, red = +12V** (the thick extra pair is red/green, but green is NOT ground; I guessed wrong at first). Board: green→GPIO16, white→GND. Colour order changed GRB→**BRG (order 2)** because WLED's orange showed purple. The green test was sent but the user unplugged before confirming, so verify on next power-up. WLED power limiter off (`maxpwr 0`, it assumes 5V). The board needs its own power (USB now). The user unplugged everything until the controller they ordered arrives (~2026-11-02). The strip lighting only its first 3 LEDs dimly means no data (board off).
**Ordered controller:** GLEDOPTO ESP32 Mini WLED controller (DC 5–24V, WLED pre-installed), Amazon order 114-5183696-3373040, arriving 2026-11-01. Plan: it runs straight off 12V (no USB/buck needed) and replaces the bare ESP32. Set it to 100 LEDs, BRG, maxpwr 0, Wi-Fi TP-Link_2.4. In HA, remove the old WLED entry and give the new light the entity id `light.camper_led_strip` so the Porch tiles and the Goodnight script keep working.

**2026-11-02 GLEDOPTO installed:** the user hooked up the GLEDOPTO ESP32 Mini (MAC d4:e9:f4:f7:d9:40, WLED 0.15.2, factory build). Set up over its WLED-AP (default pass wled1234, 4.3.2.1) using the Jetson's spare Wi-Fi radio with a temporary NM profile (deleted afterward); no USB needed. Now **192.168.0.253**, wled-camper.local, name "Camper LED Strip", 100 LEDs, BRG (order 2), WS281x, maxpwr 0, Wi-Fi TP-Link_2.4. Factory config had two outputs (GPIO16 and GPIO2); I kept only **GPIO16**, so a dark strip may mean it's wired to the other output. Button GPIO17 and relay pin 18 left at factory values. HA: old entry deleted, new entry 01M6DVG4RHTZAEE2J5K5Z69W0N, entity id stayed `light.camper_led_strip`. The bare ESP32 (.183) is retired. No DHCP reservation yet.
**2026-11-02 colour test:** with order BRG, a red/green/blue three-section test showed red, green, blue in the right sequence from the controller end, so BRG is confirmed and GPIO16 is the right output. The user first said "the colors aren't right" while it showed WLED's default orange (255,160,0); a deeper orange (255,70,0) looked right, "orange all the way" along the strip, so reach and power are fine. Later that day the user asked for "blue or purple" at startup; saved purple (128,0,255) as boot preset 1. User then asked it to stay off until turned on, so preset is "Startup Off Purple" (def.ps=1, on false, bri 128): boots off, turns on purple.

**2026-11-03 awning install:** the strip replaces the factory awning LED strip; the user can't get power at the existing plug (cause not found yet). **2026-11-03 boot-on:** at the user's request the strip now comes on with power: preset 1 renamed "Startup On Purple" (on true, bri 128, purple 128,0,255), def.on true. Replaces the earlier boot-off setting. Tested by reboot. Side effect: any power return also lights it.
**2026-11-03 color gamma on:** the GLEDOPTO's factory config had color gamma OFF, shown in /json/cfg as light.gc.col = 1 (1 means off, 2.8 means on; per WLED 0.15.2 cfg.cpp). That made strip colors paler than the WLED page and explains the earlier "orange looks wrong". Now gc col 2.8, bri 1, val 2.8; survives reboot. Awaiting user's visual confirmation.
